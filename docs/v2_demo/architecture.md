# V2 Demo Architecture

## 1. Goal

V2 adds a portfolio-ready web demo on top of the v1 PyTorch pipeline. The demo
is an ML pipeline explorer, not a replacement for the v1 training and
evaluation scripts.

The frontend is a Vite + React + TypeScript single-page app ported from the
Claude Design handoff. The MVP is fully static — the frontend reads
pre-generated JSON and PNG artifacts with no Python backend required. A later
milestone can add a FastAPI backend for live checkpoint inference.

Canonical design reference: `docs/v2_demo/frontend-design-handoff-v2.md`

## 2. High-level flow

```text
Curated sample manifest
        |
        v
Saved v1 artifacts
  ultrasound, target mask, probability map, prediction mask, metrics
        |
        v
Vite + React static frontend
        |
        +--> Hero player with stable media stage
        +--> Threshold section
        +--> Geometry section
        +--> Metrics section
        +--> Method section
```

Future live inference adds:

```text
Selected curated image
        |
        v
FastAPI checkpoint inference adapter
        |
        v
JSON compatible with the same React Sample interface
```

Arbitrary upload is a later, explicitly approved extension. The first live mode
is curated-sample-only so it can reuse known spacing, target metadata, and demo
copy without turning the app into a public medical-image upload tool.

## 3. App modes

### Saved-output mode

Saved-output mode is the v2 MVP.

Responsibilities:

- load a small manifest of curated samples,
- read exported demo artifacts,
- display each pipeline stage without loading a model checkpoint,
- keep one stable media frame while stage overlays change,
- compute lightweight interactive geometry variants when needed,
- reuse the same player shell for later live inference mode.

This mode should run without raw HC18 data or checkpoints if the curated
artifacts are present. Existing files under `outputs/runs/<run_id>/` can seed
the export, but the app should read the stable demo bundle instead of reaching
back into raw HC18 paths at runtime.

### Live-inference mode

Live-inference mode is a later extension.

Responsibilities:

- load a PyTorch checkpoint,
- preprocess selected curated images,
- run model inference,
- produce the same stage objects as saved-output mode,
- return live-generated image assets as URLs or data URLs through component
  asset overrides,
- use the existing deterministic geometry utilities.

This mode may require a checkpoint and either the local HC18 sample source or an
approved curated live bundle. It must keep the safety disclaimer visible and
must not become a dependency of saved-output mode.

Implementation plan:
See `docs/v2_demo/live-inference-plan.md`. The first implementation should use
`demo_live/` as the FastAPI companion server and keep `frontend/public/samples/`
manifest loading unchanged for static replay.

Manifest loading behavior (`frontend/src/data/samples.ts`):
The app attempts to load `/samples/manifest.json` first. If that request returns a
non-200 status (e.g., real artifacts are absent on a public host), it automatically
falls back to `/demo-samples/manifest.json`. The `demo-samples` manifest uses
`assetBasePath` and `assetExtension` fields to point components at SVG assets
instead of PNGs; the `sampleAssetPath()` helper respects these overrides.

Path A public-static deployment now uses `frontend/public/samples/` as the
preferred source on every host. `preferredManifestPath()` returns
`DEFAULT_MANIFEST_PATH` unconditionally, and the existing fallback handles hosts
where the real curated bundle is absent.

Dev/build commands:
```bash
cd frontend && npm install && npm run dev    # dev server → localhost:5173
cd frontend && npm run build                 # production → frontend/dist/
```

## 5. App-facing data contract

The frontend TypeScript `Sample` interface is the authoritative data contract.
The Python `DemoSample` dataclass is no longer used. See
`docs/v2_demo/frontend-design-handoff-v2.md` Section 5 for the full interface.

Summary of required fields per sample in `manifest.json`:

```typescript
interface Sample {
  id: string;                  // e.g. "296_HC"
  label: string;               // human title
  cat: 'strong' | 'typical' | 'failure';
  split: string;               // "test"
  summary: string;             // 1-line description
  metrics: {
    dice: number;
    iou: number;
    hd95_mm: number;
    hcErr: number;             // abs_hc_error_mm
    predHC: number;            // pred_hc_mm
    targetHC: number;          // target_hc_mm
  };
  predEllipse: {               // from predictions.csv ellipse columns
    cx: number; cy: number;
    rx: number; ry: number;
    rot: number;               // RADIANS (convert from ellipse_angle_deg)
  };
  contourHC: number;           // mm — computed by export script from cleaned mask
  confidence: number;          // mean prob inside predicted mask — from prob.png
  spacingXMm: number;          // spacing_x_mm from predictions.csv
  spacingYMm: number;          // spacing_y_mm from predictions.csv
  resolution: { w: number; h: number };  // px dimensions of exported images
  thresholdCurve?: {              // optional — pre-computed during export
    thresholds: number[];         // [0.10, 0.15, ..., 0.90]
    dice: number[];               // Dice at each threshold (same length)
    optimalThreshold: number;     // threshold that maximizes Dice
    optimalDice: number;
  };
  notes?: string;
  assetBasePath?: string;         // demo-samples fallback only — override /samples/<id>/
  assetExtension?: string;        // demo-samples fallback only — e.g. ".svg"
}
```

The frontend TypeScript interface is the authoritative contract. See Section 5 above
and `docs/v2_demo/frontend-design-handoff-v2.md` Section 5.

## 6. Manifest schema

The manifest is at `outputs/demo_samples/manifest.json` (generated by V2.S2)
and copied to `frontend/public/samples/manifest.json` before the frontend builds.
Image paths are not stored in the manifest — the frontend derives them as
`/samples/<id>/<file>.png` using each sample's `id`.

```json
{
  "schema_version": 2,
  "created_from_run_id": "attention_unet_local_baseline",
  "created_from_split": "test",
  "safety_text": "Educational demo only. Not for clinical use.",
  "samples": [
    {
      "id": "296_HC",
      "label": "Near-perfect HC",
      "cat": "strong",
      "split": "test",
      "summary": "Excellent overlap and near-perfect head-circumference measurement.",
      "metrics": {
        "dice": 0.9907,
        "iou": 0.9816,
        "hd95_mm": 0.70,
        "hcErr": 0.03,
        "predHC": 191.44,
        "targetHC": 191.47
      },
      "predEllipse": {
        "cx": 205.4, "cy": 114.2,
        "rx": 83.1, "ry": 66.7,
        "rot": 2.872
      },
      "contourHC": 192.20,
      "confidence": 0.97,
      "spacingXMm": 0.1367,
      "spacingYMm": 0.1384,
      "resolution": { "w": 384, "h": 256 },
      "notes": "Best success-path example."
    }
  ]
}
```

Notes on generation:
- `predEllipse.rot` is `ellipse_angle_deg * pi / 180` (convert from degrees)
- `contourHC` is computed at export time from cleaned mask using `src/utils/geometry.py`
- `confidence` is `mean(prob_map[cleaned_mask == 1])`, requires `prob.png`
- All `metrics` values come from real v1 CSVs, not placeholder values
- `cat` uses `'failure'` not `'edge'`

## 7. Core components

The frontend components are defined in the redesign handoff. See
`docs/v2_demo/frontend-design-handoff-v2.md` for the full component inventory
and porting instructions. Summary:

### HeroPlayer + MediaStage + Transport
The hero is the player. A stable 4:3 media frame stays fixed while stage
overlays fade in and out. `Transport` owns play/pause/seek plus the future live
status and timing slot.

### CasePickerCompact + SubNav
The standalone gallery and guided tour are removed in the redesign. Sample
selection moves into a compact six-button picker inside the hero, and the nav
shrinks to five scrollspy sections plus a mode toggle stub for future live mode.

### ThresholdSection
Canvas-based re-thresholding of `prob.png` remains the key interaction, but the
section now sits below the hero and uses a stable stage frame plus quieter
screen-blended cyan/amber overlays rather than the old full-image wash.

### CNN prediction visualization

Saved-output mode must show the exported `prob.png` and `pred.png` artifacts.
If probability-map export fails for a sample, validation should fail rather than
letting the app pretend to show probabilities.

Live-inference mode can add probability heatmaps directly from model logits.

### Geometry visualization

This view uses existing geometry utilities where possible:

- thresholded mask,
- largest connected component cleanup,
- contour measurement,
- ellipse fit,
- HC in millimeters.

It should always show the contour-vs-ellipse comparison when both measurements
are available, because this was one of the strongest v1 findings. The redesign
adds both a single-sample verdict panel and a dataset-level stripe chart so the
UI can explain how one sample may favor contour even when ellipse is more robust
overall.

### MetricsSection + MethodSection

The v2 redesign removes the old experiment dashboard from the main page. The
metrics section stays as a 2×2 set of interpretable metric cards, while a new
`MethodSection` explains architecture, training setup, and the geometry prior in
three narrative cards. Existing experiment JSON stays in the repo for possible
future use, but it is not part of the redesigned main flow.

## 8. Artifact export step

Before building the React app, revise the export script so it creates the
saved-output demo bundle required by the design:

```text
scripts/export_demo_artifacts.py
scripts/validate_demo_manifest.py
```

This export step requires local HC18 raw data at `data/raw/HC18/training_set/`
because the original image and annotation-derived target mask are not already
part of the raw-data-free demo bundle. After export, the React saved-output mode
must run without `data/raw/HC18/` or a model checkpoint.

The exporter should:

1. choose a fixed set of internal-test samples from v1 prediction/evaluation
   artifacts, using `docs/v2_demo/curated-samples.json` or explicit
   `--sample-id` arguments,
2. copy or render `ultrasound.png`, `target.png`, and `pred.png` into
   `outputs/demo_samples/<sample_id>/`,
3. run local checkpoint inference once to export `prob.png` as the raw sigmoid
   probability map,
4. compute cleaned-mask contour HC in millimeters and store it as `contourHC`
   in the manifest,
5. compute confidence, prediction ellipse, pixel spacing, and image resolution
   fields required by the TypeScript `Sample` contract,
6. write per-sample `metadata.json` for traceability,
7. write `outputs/demo_samples/manifest.json`,
8. avoid committing raw HC18 files, generated medical-image bundles, or
   checkpoints unless the user explicitly
   approves a separate artifact policy.

The validator should confirm required files exist, required fields have numeric
types, `contourHC` is non-null when contour measurement succeeds, `prob.png` is
present for every sample, and the manifest includes both strong and failure
examples.

## 9. Distribution policy

The repository now allows the curated derivative public demo bundle under
`frontend/public/samples/`, but raw HC18 images and checkpoints still remain
private by default. `outputs/demo_samples/` stays the generated local source
bundle.

The current `.gitignore` ignores `outputs/*`, including `outputs/demo_samples/`,
which is the correct default for local generated artifacts. If portfolio
screenshots or GIFs are approved later, place them in a non-ignored documentation
path such as `docs/v2_demo/screenshots/` rather than under `outputs/`.

For portfolio polish, continue to prefer:

- keeping raw HC18 files and checkpoints out of the repo,
- committing only the tiny curated derivative bundle needed by the public demo,
- adding screenshots/GIFs in documentation paths when useful.

Public hosting fallback:
The committed app keeps non-medical preview assets under
`frontend/public/demo-samples/`. The manifest loader in `samples.ts` now tries
`/samples/manifest.json` first on every host; on any non-200 response it falls
back to `/demo-samples/manifest.json`. This keeps the production site on the
real curated bundle while preserving a safe fallback.

Artifact mirror rule:
`outputs/demo_samples/` is the generated source of truth. `frontend/public/samples/`
is a publish mirror populated by `start_demo.sh` or a deliberate sync-copy.
Never hand-edit files under
`frontend/public/samples/` — regenerate from the export script and re-copy. This
prevents the mirror from diverging from the manifest metadata.

## 10. Boundaries

- The demo must not mutate raw data or split files.
- The demo must not train models.
- The demo must not silently regenerate v1 experiments.
- Saved-output mode must work offline once artifacts are present (no network required).
- Live-inference mode requires network access to the FastAPI companion server.
- Public Vercel deployment requires network access for asset delivery.
- The demo is educational and not for clinical use.

## 11. Live API Response Contract

The TypeScript types below are the authoritative interface between the React app and
the FastAPI demo server. The Pydantic models in `demo_live/schemas.py` must be kept
in sync with these types.

### TypeScript (frontend/src/types/live.ts)

```typescript
type SampleAssets = {
  ultrasound?: string;  // URL or data:image/png;base64,... string
  target?: string;
  prob?: string;
  pred?: string;
  attention?: Record<string, string>;  // gate name → URL or data URL
};

interface LiveInferResponse {
  mode: "live";
  runtime_ms: number;
  step_times_ms?: Record<string, number>;  // optional per-step breakdown
  sample: Sample;
  assets: SampleAssets;
}

type LiveStatus = "idle" | "waking" | "running" | "done" | "error";

interface LiveErrorResponse {
  error: string;     // machine code — see Section 5 error codes
  detail: string;    // human-readable message
  runtime_ms: number;
}
```

### Pydantic (demo_live/schemas.py)

```python
from pydantic import BaseModel
from typing import Optional

class SampleAssets(BaseModel):
    ultrasound: Optional[str] = None
    target: Optional[str] = None
    prob: Optional[str] = None
    pred: Optional[str] = None
    attention: Optional[dict[str, str]] = None  # gate name → URL or data URL

class LiveInferResponse(BaseModel):
    mode: str = "live"
    runtime_ms: float
    step_times_ms: Optional[dict[str, float]] = None
    sample: dict  # Sample-compatible dict; validate against Sample fields in tests
    assets: SampleAssets
```

Asset format note: each asset field is either a same-origin file URL or a base64
data URL. The frontend must not assume either format — both work with `<img src>`
and `canvas.drawImage`.

Attention asset keys: use the decoder layer names from the hook registration.
Expected keys for the first live milestone: `"decoder4"`, `"decoder3"`. Maps are
grayscale PNGs at the same pixel dimensions as `prob.png`.

### Hosted curated-bundle data requirements

For live mode on a hosted backend (Google Colab, HF Spaces), the curated bundle
stored on Google Drive must include per sample:

```text
<sample_id>/ultrasound.png  — original HC18 ultrasound (256×384 px)
<sample_id>/target.png      — annotation-derived target mask (for Dice computation)
<sample_id>/spacing.json    — {"spacing_x_mm": float, "spacing_y_mm": float, "target_hc_mm": float}
best_model.pt               — trained Attention U-Net checkpoint
config.json                 — run config (same as outputs/runs/attention_unet_local_baseline/config.json)
```

This bundle is generated locally from the existing HC18 data and export script,
then uploaded to Google Drive. It must **not** be committed to the repository.
The export script's `outputs/demo_samples/` directory is the source; use it.
